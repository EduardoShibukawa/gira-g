# Prior art: Understand Anything

[Understand Anything](https://github.com/Egonex-AI/Understand-Anything): MIT, TypeScript. A coding-agent plugin whose pipeline runs inside the host agent; only `imports` edges are parsed, the rest are LLM-emitted.

## How we use this tool

Studied, never depended on. Decided in [How to reuse Graphify and Understand Anything](../../.scratch/system-context-harness/issues/10-reuse-strategy.md).

- Run only by hand, in a throwaway environment outside this repo's mise toolchain.
- Never in `mise.toml`, CI, git hooks, AGENTS.md or any agent config in this repo. Its output is never committed (see `.gitignore`).
- Reimplement ideas; don't copy. Any verbatim copy (code, prompts, fixtures, queries) keeps its upstream license header and gets an entry in `THIRD_PARTY_NOTICES`.
- Each study run appends a dated section below, naming the tool version/commit and labelling each finding **Fact**, **Inference** or **Open**.

## Ideas we borrow, and who decides them

| Idea | Decided by |
|---|---|
| Per-file structural fingerprints with skip/partial/architecture/full refresh classes; refuse to publish a map that lost a symbol unless a parser confirms it; fresh/dirty/stale and behind/ahead/diverged states | Storage and incremental refresh (map fog) |
| Committed map + read-only viewer that needs no LLM; tours as ordered ID lists | [Human-facing surface for the MVP](../../.scratch/system-context-harness/issues/16-human-surface.md) |
| Import resolution via nearest `go.mod`/`tsconfig` | [First wave of extractors](../../.scratch/system-context-harness/issues/13-first-extractor-wave.md) |

What we diverge on: no LLM-emitted edges without evidence; no fixed per-type weights; IDs must survive renames; no unverified LLM summaries in the Macro Map.

## How we use it: USE / COPY / NORTH STAR

- **USE:** nothing directly (edgeless output; only `imports` is deterministic). Possible future optional adapter for `summary`/`tags`/`layers`/`tour` as unverified annotations only.
- **COPY:** fingerprints + SKIP/PARTIAL/ARCH/FULL; symbol-loss gate (never publish a smaller map without proof); fresh/dirty/stale + behind/ahead/diverged staleness; committed map + read-only viewer; tour as ID list; tolerant ingestion (aliases, per-item drop); nearest-manifest resolution (covering workspaces + tsconfig references).
- **NORTH STAR:** deterministic first, LLM second with structural signals; prose pipelines and LLM-authored scripts don't reproduce — ship the scripts.

### Summary

- Understand Anything (UA) is **not a standalone tool**. It is a coding-agent plugin: markdown skills (`/understand`, `/understand-domain`, …) and agent prompts that tell the host agent (Claude Code, Codex, Cursor, Copilot, Gemini CLI, …) to run bundled Node/Python helper scripts, start LLM subagents, and merge their JSON. Most of the orchestration (phases, retries, gates) is written as prose in `SKILL.md`, not as code.
- **Split between deterministic and LLM work:** tree-sitter (WASM) plus a resolver produce file inventory, symbols, call sites and **`imports` edges** without an LLM. **All other edge types** (`calls`, `depends_on`, `configures`, `deploys`, `routes`, …), plus summaries, layers, tours and domain flows, come from the LLM.
- **Schema:** one flat `knowledge-graph.json` holding nodes, edges, layers, tour and project meta. The node unit is a **file or symbol**, never a Component. Edges have **no evidence, provenance or confidence field**: `weight` is a fixed value per edge type. Nothing in the schema separates a parsed edge from an LLM-guessed one.
- **Incremental updates are the most engineered part.** It keeps per-file structural fingerprints, classifies changes into SKIP / PARTIAL / ARCHITECTURE / FULL, re-analyzes only structurally changed files, and runs a strict "symbol-loss gate" before publishing.
- **Not tied to an LLM vendor, but tied to an agent host.** There is no LLM SDK or API key in the code. The LLM work runs through the host agent's subagents.
- MIT license. Very active (about 86k stars, about 320 open issues, commits as of 2026-10-09). Mostly one maintainer. Needs Node ≥22, pnpm ≥10 and Python 3.
- **For a Go/Rust harness:** reuse ideas, not code. An optional import adapter is possible, but the data has low evidential value. The ideas worth adopting are the fingerprint-based incremental classification, the staleness model, "commit the graph + read-only viewer", tours as ordered node lists, tolerant validation of LLM output, and per-manifest import resolution.

### 1. Structural extraction

Agents are told not to reimplement it. ([P/agents/project-scanner.md L18](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/agents/project-scanner.md))

### 6. Incremental updates

- **Fact.** Structural fingerprints are SHA-256 content hashes plus normalized function/class/import/export signatures with export status. Files without a tree-sitter parser get a content-hash-only fingerprint, which is the conservative choice. Each file is classified `NONE | COSMETIC | STRUCTURAL`. ([P/packages/core/src/fingerprint.ts L58-81, L278-313](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/fingerprint.ts))
- **Fact.** Update classes ([P/packages/core/src/change-classifier.ts L4-19](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/change-classifier.ts)):
  - **SKIP:** only cosmetic changes.
  - **PARTIAL:** structural changes inside the same directories.
  - **ARCHITECTURE:** new or deleted directories, or more than 10 structural files. Layers and tour are re-run.
  - **FULL:** more than 30 structural files, or more than 50% of files.
- **Fact.** `prepare-incremental.mjs` runs `git diff --name-status -z` from the last analyzed commit, re-scans, compares fingerprints, refreshes imports for affected files, and prunes changed or deleted paths from the old graph ([P/skills/understand/SKILL.md L195-226](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/SKILL.md), [P/skills/understand/prepare-incremental.mjs L422-450](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/prepare-incremental.mjs)). On PARTIAL, layers are reassigned deterministically (deepest common directory, then connectivity) and tour steps only lose dangling IDs ([SKILL.md L472, L557](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/SKILL.md)).
- **Fact.** The **symbol-loss gate** checks every function, class and method that disappeared. Each must be confirmed deleted by a strict parser with scoped declaration coverage. Otherwise publishing is blocked, and one targeted LLM retry is allowed. Coverage adapters exist for JS/TS, Ruby, Python, Go, Rust and C++. Other languages "remain conservative" and block. ([SKILL.md L413-437](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/SKILL.md); design in [UA/docs/incremental/symbol-loss-validation.md](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/docs/incremental/symbol-loss-validation.md))
- **Fact.** Triggers: a `PostToolUse` hook matches `git commit|merge|cherry-pick|rebase` in Bash tool calls. A `SessionStart` hook compares `meta.json` against HEAD. Both inject "You MUST read auto-update-prompt.md … Do not ask the user for confirmation". Neither updates the graph by itself. ([P/hooks/hooks.json](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/hooks/hooks.json), [P/hooks/post-tool-use-auto-update.mjs](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/hooks/post-tool-use-auto-update.mjs))
- **Fact.** Freshness model: `fresh | dirty | stale`, with relation `behind | ahead | diverged` and explicit unknown reasons ([P/packages/core/src/staleness.ts](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/staleness.ts)).
- **Inference.** `pruneExistingGraph` drops every edge whose target is a node of a re-analyzed file. That includes LLM-emitted `calls`/`depends_on` edges from **unchanged** files. Only `imports` (restored from importMap) and `tested_by` (path convention) come back by deterministic means. Inbound semantic edges therefore wear away across incremental runs until a FULL rebuild. ([prepare-incremental.mjs L441-447](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/prepare-incremental.mjs))
- **Fact.** Token cost is unmeasured. There is no published end-to-end token or cost figure ([#657](https://github.com/Egonex-AI/Understand-Anything/issues/657), open). The large-repo benchmark covers only the deterministic stages and says so ([UA/docs/benchmarks/large-monorepo.md](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/docs/benchmarks/large-monorepo.md)).

### 7. Data schema

- **Fact.** Root: `KnowledgeGraph { version, kind?: codebase|knowledge|design, project: {name, languages, frameworks, description, analyzedAt, gitCommitHash}, nodes, edges, layers, tour }` ([P/packages/core/src/types.ts L97-115](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/types.ts)).
- **Fact.** There are 27 node types: code (file, function, class, module, concept), non-code (config, document, service, table, endpoint, pipeline, schema, resource), domain, knowledge and Figma design types. There are 38 edge types in 9 categories. ([types.ts L1-21](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/types.ts))
- **Fact.** Node: `{id, type, name, filePath?, lineRange?, summary, tags, complexity, languageNotes?, domainMeta?, knowledgeMeta?, figmaMeta?}`. Edge: `{source, target, type, direction: forward|backward|bidirectional, description?, weight 0..1}` ([types.ts L54-77](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/types.ts)).
- **Fact.** IDs are type-prefixed paths: `file:<path>`, `function:<path>:<name>`, `class:<path>:<name>`, `service:<path>`, and so on ([SKILL.md L892-910](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/skills/understand/SKILL.md)). **Inference:** IDs are path-based, so a rename means a new identity.

- **Fact.** **No evidence, provenance or confidence on edges.** The edge schema has no source-location, method or extractor field ([types.ts L70-77](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/types.ts)). ### 10. What a Go or Rust harness could reuse

**Code reuse: none.** **Fact:** UA is TS + Python + prompts. **Inference:** its orchestration only runs inside an agent host, so nothing can be linked or embedded in a single binary.

**Option A: consume its output through an adapter (low value, optional).**
- **Inference.** `knowledge-graph.json` is simple to parse: plain JSON, documented TS types, file-path-keyed IDs. A Go/Rust importer could bring in `summary`/`tags` per file, `layers` and `tour` as **unverified, human-facing annotations** attached to files inside our Components.
- **Inference.** UA edges should not be imported as Macro Map relationships. They carry no evidence, and only `imports` is deterministic; we would re-derive those ourselves anyway. Its `service` nodes are files, not Services. Its granularity (file/function) sits below our Component unit.
- **Open.** Whether users actually have committed `.ua/` graphs worth ingesting. The README suggests committing them; real adoption is unknown.

**Option B: adopt ideas (recommended).**
1. **Fingerprint-based change classification.** Hash content plus normalized signature (exports, functions, classes, imports), sort each change into NONE / COSMETIC / STRUCTURAL, and escalate by threshold (SKIP / PARTIAL / ARCH / FULL). This maps directly onto refreshing a Component map: re-derive only Components whose structural fingerprint changed. ([fingerprint.ts](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/fingerprint.ts), [change-classifier.ts](https://github.com/Egonex-AI/Understand-Anything/blob/ffa2f0a84a85525623e9f94f7a6b560e39ae43ce/understand-anything-plugin/packages/core/src/change-classifier.ts))
2. **"Never publish a smaller graph without proof."** The symbol-loss gate becomes, at Component level: a Component or relationship may disappear only with positive deletion evidence. Otherwise mark it unknown or blocked. This matches our "unsupported/unknown instead of guessing" rule.
3. **Staleness model** (`fresh/dirty/stale`, `behind/ahead/diverged`, explicit unknown reasons), and slices that warn when the map is behind the working tree. Freshness is scoped to the project path, so a monorepo sibling change does not mark everything stale.
4. **Commit the map + read-only viewer.** Generated artifacts committed to the repo, viewable with no LLM. This fits a single binary well: `harness serve` reading a committed map.
5. **Tours as ordered lists of node IDs with narrative.** A cheap, schema-light way to serve an onboarding slice to humans and agents.
6. **Tolerant ingestion of LLM output.** An alias table for types, directions and enums; per-item drop with a recorded issue; fatal only on structural emptiness. Useful wherever we let an LLM propose relationships.
7. **Per-manifest import resolution** (nearest `go.mod` / `tsconfig` per file). This is already Component-shaped. Learn from their open gaps: workspace package names (#589) and tsconfig `references` (#706) need resolving, or monorepo maps starve.
8. **Deterministic first, LLM second, with structural signals passed in** (import map, neighbor map, fan-in/fan-out, BFS from the entry point). The idea is good. Their implementation lets the LLM write the analysis scripts at runtime; ours should ship them.

**Anti-patterns to avoid (Inference, based on the facts above):**
- Edges with no evidence or provenance, and a `weight` that looks like confidence but is a constant per type.
- Pipeline logic in prose prompts, and LLM-authored throwaway scripts. The result cannot be reproduced or tested.
- Path-based IDs with no rename identity.
- Incremental pruning that silently loses inbound semantic edges.
- No token or cost budget ever measured end to end (#657).

### Open / unknown

- Real end-to-end token cost and wall time per repo size. The project has not published them (#657).
- Accuracy of LLM-emitted `calls`/`deploys`/`configures` edges. There is no precision/recall evaluation in the repo.
- Whether the inbound-edge loss in PARTIAL updates is reported upstream or offset elsewhere. I found no offsetting code.
- Graph schema versioning and migration policy beyond the hard-coded `"1.0.0"`.
- Quality of the committed microservices-demo graph the README cites. It is not in this repo and was not inspected. It could be a quick qualitative comparison point on a candidate Reference Corpus.
